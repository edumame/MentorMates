# Scraper quota deployment

The additive migration and disposable test harness are under supabase/migrations/ and scripts/. The harness passed against PostgreSQL 16.15 with 30 independent sessions: 5 allowed, 25 denied; both client roles denied table access and RPC; user isolation, two rollovers and Retry-After checked. Container uses network none/tmpfs/no published ports and is removed in finally. CI should run `python3 scripts/test_scraper_quota.py` on Ubuntu with Docker. No live database URL option or app schema bootstrap.

Before merging/deploying route changes, apply the additive migration to the intended database through its normal reviewed deployment mechanism. No linked Supabase project has been provided, so this prerequisite has NOT been performed. Verify service-role RPC permission and a successful disposable-user reservation there without posting keys. Routes must return 503 and avoid TinyFish/proxy calls when the RPC is missing or errors; never fall back to an in-memory counter. Deploying code first will intentionally disable imports until the migration is present.

Both routes must share this RPC and use auth.getUser-derived UUIDs only, never a body-supplied user ID. The service role calls a SECURITY DEFINER function with fixed pg_catalog search_path, fully qualified table, and PUBLIC/anon/authenticated execution revoked. No application tables or historical migrations needed. Storage is one row per user that has attempted import; retention can be added later. The table intentionally has no auth.users FK so the migration and fixture are standalone; deleted users may leave non-content quota rows until maintenance.

Quota is 5 attempts per UTC clock hour, shared across both endpoints. Atomic UPSERT reserves before network work. Failed upstream calls still consume slots. Fixed windows permit up to 10 calls around an hour boundary; account farming and total tenant expenditure require separate operational controls, not claims of a universal spending ceiling.

Proxy requires a configured server-only shared authentication token (e.g. EVENT_SCRAPER_API_TOKEN) and an HTTPS configured destination before spending quota or fetching. Deploy/configure token enforcement at the remote scraper first. Do not forward user cookies or add a token bypass to the local browser-facing scraper route. Missing configuration returns 503. Validate integration config without disclosing keys.

Target URL policy: HTTPS, bounded length, no userinfo/IP literals/nonstandard ports; default devpost.com and its subdomains, documented exact hostname opt-ins for custom event sites. Validate suffix boundaries (evildevpost.com must fail). Provider traversal redirects/linked pages remain outside local control; TinyFish must enforce network/egress restrictions. URL admission is not proof of complete SSRF prevention.

Remote service contract: EVENT_WIZARD_SPEC.md lines 317–320 describes porting from a separate event-scraper project; the proxy handler also explicitly describes calling its deployed API. Its test fixture uses event-scraper.vercel.app. This establishes intended separation, not proof of actual deployed configuration. EVENT_SCRAPER_API_URL must name a separate service implementing the shared-token protocol. Do not point it at this repository's newly hardened cookie-authenticated /api/scrape route: that route intentionally has no shared-token bypass. Verify the target's token rejection/acceptance before enabling the proxy changes.

Run `python3 scripts/test_scraper_quota.py` from the repository. Latest run also validates a stored window ahead of the request's computed window: reservations never move it backward, counts remain cumulative, and denial retry derives from the stored window rather than a stale request window. Retry is capped at 3600 seconds. Full harness passed after these SQL changes.


Runtime configuration: `SCRAPER_ALLOWED_HOSTS` is a comma-separated list of exact additional hostnames (no scheme, port, or wildcard). Devpost and its subdomains are enabled by default. `EVENT_SCRAPER_API_URL` is the separate HTTPS service base URL; `EVENT_SCRAPER_API_TOKEN` is sent as a server-only Bearer token. `TINYFISH_API_KEY` enables the direct provider route. Authenticated users share five attempted imports/hour across both endpoints. A URL query parameter now prefills the form only; the user must explicitly submit to spend an attempt.

Requests are capped at 8 KiB, URLs at 2048 characters, provider/proxy bodies at 2 MiB, JSON reads at 15 seconds, and provider fetches at 240 seconds. Missing config/quota infrastructure returns 503. Invalid input returns 400, unauthenticated requests 401, exhausted quota 429 with Retry-After, and upstream failures 502 with sanitized messages. Incoming request timeout 408 / oversize 413 are returned by either handler; proxy response parsing always maps remote failures to 502.
